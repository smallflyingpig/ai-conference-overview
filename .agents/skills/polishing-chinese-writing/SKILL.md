# 自然中文润色

## 核心原则

先理解，再改写。让中文读者直接看懂作者想说什么，同时完整保留事实边界；不能机械替换所谓“问题词”。

## 工作流程

1. 锁定不能变化的信息：数字、时间、比较对象、肯定或否定关系、不确定程度、引用关系、专有名词和代码标识。
2. 记录用户点名不希望出现的词和语气。把它们视为明确要求，不要换个位置继续使用；改写完成后逐项搜索，除非它是不可改动的专有名词，否则应从读者看到的文本中消失。
3. 判断受众和文体。网页面向读者，优先直接、具体；研究报告可以保留必要术语，但要解释术语在当前句子中的作用。
4. 找出阅读阻力：翻译腔、内部工程黑话、抽象名词堆叠、中英混杂、被动句、过长定语、空泛的“进行/相关/基于/赋能”。
5. 按意思重组句子：补出明确主语，用具体动词替代抽象名词，把一条过长的逻辑链拆成两句。
6. 需要处理“门禁、约束、核验、证据、结论”等高频技术腔，或 `lineage / audit / gate / withheld` 等混杂表达时，完整阅读 [按语境改写指南](references/rewrite-guide.md)。
7. 完成自检，再交付。

## 术语保留

保留论文标题、模型名、benchmark、API、字段名、代码、SHA-256、Pass@k、Wilson 95% CI 等精确表达。通用英文概念改成自然中文；中文可能失真时，第一次出现采用“中文（English）”，后文使用更易读的简称。

## 自检

- **事实**：数字、范围、方向、条件和不确定性是否与原文一致？
- **自然**：读出声是否像中文作者会说的话？主语和动作是否清楚？
- **具体**：“依据”“结果”“来源”“限制”等词是否指向了具体对象？
- **简洁**：删去套话后，信息是否仍然完整？
- **一致**：标题、按钮、图注和正文是否使用同一套称呼？
- **用户要求**：逐项搜索用户点名的生硬表达，确认没有在标题、按钮或正文中残留。

## 交付方式

默认只交付改写后的正文，保留原文结构和 Markdown/HTML 格式。只有用户要求时，才附修改说明、术语表或逐段对照。若原文存在事实歧义，先指出歧义；不要靠润色替作者补出未经支持的判断。

## 示例

原文：

> 该主题通过质量门禁，但结论仍受单年快照约束。50 篇审计样本中 48 篇判断正确，Wilson 95% CI 下界为 0.865399。

改写：

> 人工抽查的 50 篇论文中，有 48 篇分类正确，Wilson 95% 置信区间下界为 0.865399，因此这组统计结果可以用于介绍 ACL 2026。由于目前只有一年的数据，还不能判断它是否构成长期趋势。

## 常见错误

| 错误 | 修正方式 |
|---|---|
| 逐词寻找“高级”近义词 | 回到整句要表达的事实，重新组织主语、动作和对象 |
| 为了专业而保留整串英文 | 只保留不可替代的名称或指标，其余用中文说明 |
| 为了顺口删掉限定条件 | 先锁定范围、否定关系和不确定性，再改句式 |
| 每句话都解释编辑过程 | 默认只给读者需要的最终文本 |
