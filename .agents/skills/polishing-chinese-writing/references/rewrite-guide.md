# 按语境改写指南

这份表用于发现问题，不是替换字典。不要整表查找替换；要根据句子实际表达的意思选择说法，必要时重写整句。

| 原表达 | 常见问题 | 可考虑的自然说法 |
|---|---|---|
| 门禁、gate | 像内部流程名，读者不知道通过什么 | 发布标准、检查要求、达到要求、可以纳入分析 |
| 约束、constraint | 抽象，容易掩盖真正限制 | 只适用于、前提是、范围限于、受到……影响 |
| 核验、verify | 公文腔，动作对象不清 | 确认、查证、对照、检查 |
| 结论、claim | 频繁出现会显得生硬 | 主要发现、分析结果、目前可以判断、论文显示 |
| 证据、evidence | 容易成为万能空词 | 论文结果、统计数据、官方信息、引用来源、判断依据 |
| 审计、audit | 容易让研究质量检查像财务审计 | 人工抽查、质量检查、复核记录 |
| lineage | 直接保留英文会阻断阅读 | 处理记录、版本变化、分类过程、来源链 |
| contract | 工程内部定义误入正文 | 统计定义、数据格式、发布要求、约定 |
| artifact | 不说明是什么文件 | 数据文件、分析结果、构建产物 |
| assignment | 容易误译为“赋值” | 分类结果、分组结果、标签 |
| snapshot | “快照”未必适合研究叙述 | 当年数据、单年概览、当前统计 |
| withheld | 直接保留英文不利于理解 | 暂不展示、暂不纳入主要分析、信息不足，暂不判断 |
| experimental | 容易被理解为“做过实验” | 暂定结果、仅供参考、仍需更多检查 |
| paper-reported | 机械翻译不自然 | 论文报告的结果、作者在论文中给出的结果 |
| transfer implication | “迁移启示”含义模糊 | 对后续研究的启发、可以借鉴的方法、可能的应用价值 |

## 三类文体

### 网页和产品文案

先说读者能看到什么、为什么值得看、哪里存在限制。按钮使用动作，如“查看论文解读”“了解统计方法”，避免“进入证据层”。

### 研究综述

区分“论文报告的结果”“多篇论文共同呈现的方向”和“作者的进一步判断”。限定条件放在相关判断附近，不要统一堆到文末。

### 方法说明

可以保留精确字段名和统计术语，但先用一句普通中文说明它解决什么问题。字段名放在代码格式中，不让内部数据结构主导整段叙述。

## 句子级检查

发现以下结构时，优先重写整句：

- 三个以上抽象名词连续出现，如“证据核验门禁约束”；
- 连续使用“基于、通过、围绕、面向、进行”；
- 主语缺失，只有“实现了、完成了、形成了”；
- 中英文逐词对应，但中文读者仍需反向翻译；
- 把“没有足够数据”包装成“未通过某种 gate”。
