# 论文中文阅读体系设计

**日期：** 2026-08-25

**适用范围：** ACL 2026 long papers；后续可复用于其他已配置会议

**目标：** 为每篇论文提供适合中文读者学习的独立页面，同时保持获奖论文深度解读与普通论文摘要总结之间的内容层级差异。

## 1. 背景与目标

当前网站已经收录 ACL 2026 的 2,222 篇 long paper，并为 30 篇官方获奖论文提供了英文深读材料和简短中文解读。普通论文目前只有标题、作者、主题和官方链接，获奖论文页面的中文内容也不足以形成完整的学习路径。

本次改造拆成两个独立任务：

1. 为 30 篇获奖论文提供详细中文解读；
2. 为其余 2,192 篇论文提供覆盖核心内容的中文摘要总结。

两类论文共用统一的详情页入口、来源说明和版本记录，但使用不同的内容模板与制作流程。普通论文不会因为摘要较长而被包装成“深度解读”，获奖论文也不会直接复用普通摘要代替 PDF 阅读。

## 2. 设计原则

- **中文优先：** 页面默认展示中文导读，英文摘要和英文原文材料按需展开。
- **先理解再深入：** 先回答论文研究什么、怎样解决、发现了什么，再展示实验细节和原文。
- **内容有出处：** 中文摘要以官方 title、abstract 和 PDF 为基础，不根据标题猜测论文内容。
- **不改变原意：** 保留比较对象、数字、肯定或否定关系、适用范围和不确定程度。
- **两级内容：** 获奖论文是详细解读，其他论文是 150–250 字的摘要总结。
- **静态可访问：** 每篇论文都有稳定的 GitHub Pages 路径，不依赖运行时 API。
- **可扩展：** 数据格式包含 venue、year、track 和 paper ID，后续可以用于 EMNLP、ICLR、ICML、NeurIPS、CVPR、ICCV 和 ECCV。

## 3. 页面结构

### 3.1 普通论文详情页

路径：`/papers/<route-key>/`，仅为 2,192 篇非获奖论文生成。

页面按以下顺序展示：

1. **论文信息**：英文标题、作者、会议、主要主题，以及官方页面、PDF 和 Code 链接；
2. **一句话概括**：用一句中文说明论文的核心工作；
3. **中文摘要**：150–250 个中文字符，覆盖研究问题、核心方法和主要发现；
4. **研究问题**：说明论文要解决的具体问题；
5. **核心方法**：说明最重要的技术变化，不逐段复述论文；
6. **主要发现**：只写论文明确报告的结果，数字必须能在官方摘要或 PDF 中找到；
7. **适用范围与局限**：说明实验对象、数据范围或作者明确讨论的限制；没有可靠信息时显示“论文摘要未提供更多说明”，不自行补充；
8. **英文摘要**：默认收起，供读者对照原文。

论文索引中的普通论文标题进入中文摘要页，获奖论文标题直接进入获奖深读页；“官方页面”“PDF”“Code”继续作为独立入口保留。搜索范围增加中文一句话概括和中文摘要。

### 3.2 获奖论文详情页

获奖论文保留现有 `/awards/<route-key>/` 稳定路径，并按学习顺序重组：

1. **三分钟读懂**：研究问题、核心方法、主要发现三张摘要卡片；
2. **中文摘要**：忠实概括论文整体内容，不只摘取某一项实验结果；
3. **研究背景**：说明问题为什么重要，以及已有方法的不足；
4. **方法流程**：按“输入 → 关键步骤 → 输出”解释方法，保留必要的模型名和公式；
5. **关键实验结果**：展示指标、数值、对比对象、实验条件和原文位置；
6. **为什么值得关注**：解释论文贡献与研究价值，不写成官方评奖理由；
7. **局限与研究启发**：区分作者明确讨论的限制和跨论文综合得到的进一步判断；
8. **英文原文参考**：默认收起，保留现有深读字段、来源链接和具体位置。

同一篇获奖论文不再生成普通摘要页，避免维护两套相互冲突的中文内容。论文索引和站内搜索结果直接链接到对应的获奖深读页。

## 4. 数据设计

### 4.1 普通论文中文摘要

新增独立的 JSONL 内容文件，每行对应一篇论文：

```json
{
  "schema_version": "paper-summary-zh-v1",
  "paper_id": "acl:2026.acl-long.1",
  "venue": "ACL",
  "year": 2026,
  "track": "long",
  "source_title": "Official paper title",
  "source_abstract_sha256": "<sha256>",
  "one_sentence": "一句话概括",
  "summary_zh": "150–250 字中文摘要",
  "research_problem": "研究问题",
  "core_method": "核心方法",
  "main_findings": "主要发现",
  "scope_and_limitations": "适用范围与局限",
  "content_method": "title-abstract-grounded-summary-v1"
}
```

`source_abstract_sha256` 把中文内容与当前官方摘要绑定。官方摘要发生变化时，旧中文摘要不能继续直接发布。

ACL 2026 中缺少网页摘要的论文单独读取官方 PDF，并将 `content_method` 记为 `official-pdf-grounded-summary-v1`，同时记录 PDF SHA-256。不能只根据标题生成内容。

### 4.2 获奖论文中文深读

获奖论文使用独立结构：

```json
{
  "schema_version": "award-deep-read-zh-v1",
  "paper_id": "acl:2026.acl-long.1",
  "source_pdf_sha256": "<sha256>",
  "quick_read": {
    "research_problem": "研究问题",
    "core_method": "核心方法",
    "main_finding": "主要发现"
  },
  "abstract_zh": "中文摘要",
  "background": ["背景说明"],
  "method_walkthrough": ["方法步骤"],
  "why_it_matters": ["论文价值"],
  "limitations": ["局限"],
  "research_implications": ["研究启发"]
}
```

现有英文 DeepRead 继续作为数字、实验设置和原文位置的详细来源；中文深读是面向读者的表达层，不覆盖英文数据。

### 4.3 路由键

论文详情页不直接把带冒号的 paper ID 放进 URL。生产端根据完整 paper ID 生成稳定的 `route_key`，站点只使用发布文件中的键，不自行重新计算。所有键必须唯一；生成方式变化时已有 URL 仍需兼容。

## 5. 内容制作流程

### 5.1 普通论文

1. 从正式发布数据中导出 paper ID、title、abstract、主题和官方链接；
2. 按固定批次生成结构化中文内容；
3. 导入时检查 paper ID、官方摘要 SHA-256、字段完整性和字符长度；
4. 对数字、模型名、数据集名和 benchmark 名进行一致性检查；
5. 生成覆盖清单和主题分层抽样清单；
6. 只有 2,222 篇全部有可用内容，或缺失项被明确列出并阻止正式发布时，才生成完整站点。

普通论文中文摘要不承担新的学术判断。`main_findings` 只能概括作者报告的结果；`scope_and_limitations` 只能来自摘要、PDF 或明确的实验范围。信息不足时使用直白的缺失说明。

### 5.2 获奖论文

1. 复用现有 30 篇官方 PDF 及其 SHA-256；
2. 根据完整论文内容编写中文摘要和分节解读；
3. 将中文段落与现有 DeepRead 的章节、表格或页码对应；
4. 检查论文报告的内容、跨论文综合和进一步判断是否清楚区分；
5. 逐页检查桌面端和移动端阅读体验。

## 6. 质量检查

### 6.1 完整性

- 当前发布范围中的 2,222 个 paper ID 必须各有一条中文内容，其中 2,192 条为普通摘要、30 条为获奖深读；
- 30 篇获奖论文必须各有一条中文深读，并且能够从论文索引直接进入深度解读；
- 不允许重复 ID、未知 ID、空字段或失效路由；
- 官方摘要变化后，对应中文摘要必须重新生成或重新确认。

### 6.2 内容质量

- 普通论文 `summary_zh` 为 150–250 个中文字符；
- 句子以自然中文为主，模型名、数据集、benchmark 和指标保留准确英文；
- 不使用“门禁、契约、赋值、核验”等面向内部实现的说法；
- 摘要中的数字必须能在官方摘要或 PDF 中找到；
- 不把相关性写成因果关系，不扩大作者的肯定或否定程度；
- 不用统一套话填充“局限”，信息不足时直接说明；
- 抽样按主要主题分层，避免只检查热门方向。

自动检查负责发现格式、覆盖、长度、来源版本和明显的名称或数字问题；语义是否准确仍需抽样阅读。网站的方法说明页公开摘要覆盖率、抽样方法、发现的问题和当前适用范围，不把自动检查描述成人工精读。

### 6.3 页面体验

- 桌面端与移动端都能按照阅读顺序浏览；
- 页面首屏可以直接看到一句话概括和三项核心信息；
- 英文原文默认收起，但无需 JavaScript 也能展开；
- 论文索引、普通详情页和获奖深读页之间没有死链；
- GitHub Pages 项目子路径下的所有资源和链接正确；
- 2,222 个静态详情页构建时间和产物体积记录在发布报告中。

## 7. 发布文件与站点读取

正式 release 仍保持现有六个核心文件，不把大量中文内容直接塞进 `overview.json`。新增独立、不可原地修改的中文内容包，包含：

- `paper-summaries.zh.jsonl`：2,192 条普通论文摘要；
- `award-deep-reads.zh.jsonl`：30 条获奖论文中文深读；
- `content-manifest.json`：schema 版本、内容条数、文件 SHA-256、对应的 `papers.json` SHA-256 和生成时间。

当前版本指针同时引用正式 release 与中文内容包。站点构建时先检查 content manifest，再分别读取两类内容，并将两者的 paper ID 并集与 `papers.json` 做严格的一一对应。这样不会破坏现有“正好六个文件”的 release 定义，也不会仅依赖文件路径判断版本是否匹配。

## 8. 异常处理

- 缺少官方 abstract：改读官方 PDF；PDF 也不可用时停止该论文的中文摘要发布并报告缺失原因；
- 中文内容缺少字段或长度不符合要求：导入失败，不生成半成品页面；
- 摘要与当前 paper ID 或摘要 SHA-256 不一致：视为过期内容，停止构建；
- 获奖论文缺少中文深读：获奖详情页停止生成，不退回到普通摘要伪装成深读；
- 某篇论文没有 Code 链接或作者没有报告局限：页面省略相应链接，并用准确的缺失说明代替猜测。

## 9. 测试范围

### Python

- JSONL schema、paper ID 完整覆盖和唯一性；
- title/abstract/PDF SHA-256 绑定；
- 普通摘要与获奖深读分离；
- 缺失、重复、过期和错误路由键均会失败；
- 正式发布内容包可重复生成且哈希稳定。

### Site

- Zod schema 与 Python 输出保持一致；
- 2,192 个普通论文详情路由全部生成；
- 30 个获奖页面全部生成且拥有完整中文模块；
- 论文索引中的获奖论文正确链接到深度解读；
- 搜索可以匹配标题、作者、paper ID 和中文摘要；
- 空数据构建不生成论文详情页；
- GitHub Pages base path 下的站内链接全部可访问。

### 浏览器

- 桌面端和移动端抽查普通论文、长标题论文、无 Code 论文、PDF 补充摘要论文和获奖论文；
- 中文内容位于英文原文之前；
- 页内导航、折叠原文、返回论文索引和外部链接可用；
- 页面没有横向溢出，长模型名和公式能够换行。

## 10. 实施顺序

1. 定义普通中文摘要与获奖中文深读的数据格式；
2. 实现导出、导入、来源版本检查和覆盖检查；
3. 先用小型 fixture 完成生产端和站点端测试；
4. 制作并检查 30 篇获奖论文中文深读；
5. 分批制作 2,192 篇普通论文中文摘要；
6. 生成论文详情页并改造论文索引；
7. 完成整站构建、浏览器抽查和发布报告；
8. 在用户 review 本地页面后，再进入 GitHub Pages 发布流程。

## 11. 验收标准

- 2,222 篇 ACL 2026 long paper 都有稳定的中文详情页，其中包括 2,192 个普通摘要页和 30 个获奖深读页；
- 其余 2,192 篇论文各有 150–250 字摘要总结，并覆盖研究问题、核心方法和主要发现；
- 30 篇获奖论文各有完整中文摘要与详细解读；
- 中文内容与当前官方摘要或 PDF 的版本一致；
- 获奖深读和普通摘要在数据、页面和制作方法上清楚分开；
- 所有自动测试、静态构建和浏览器检查通过；
- 本地页面经用户 review 后才允许推送和发布。
