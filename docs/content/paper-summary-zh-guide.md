# 论文中文内容写作指南

本指南用于 ACL 2026 论文中文页面，也适用于后续接入的其他会议。写作时先读懂论文，再用自然中文重新组织；不能逐句机翻，也不能根据标题补写论文没有提供的信息。

## 一、两类内容

### 普通论文摘要

普通论文使用六个字段：

1. `one_sentence`：一句话说明论文最核心的工作；
2. `summary_zh`：150–250 个中文字符，覆盖问题、方法和主要发现；
3. `research_problem`：论文具体解决什么问题；
4. `core_method`：最重要的技术变化是什么；
5. `main_findings`：作者明确报告了什么结果；
6. `scope_and_limitations`：实验适用范围，以及摘要或论文明确说明的限制。

摘要以官方 title + abstract 为基础。缺少网页 abstract 时，必须阅读绑定 SHA-256 的官方 PDF。信息不足时直接说明，不补写通用局限。

### 获奖论文深读

获奖论文必须阅读完整官方 PDF，并写清：

- 三分钟读懂：研究问题、核心方法、主要发现；
- 中文摘要；
- 研究背景；
- 方法步骤；
- 为什么值得关注；
- 局限；
- 后续研究可以借鉴的思路。

“为什么值得关注”是网站根据论文内容给出的解读，不能写成官方评奖理由。论文报告的结果、跨论文综合和进一步判断必须清楚区分。

## 二、不能改变的信息

写作前先锁定：

- 数字、单位和指标；
- 比较对象和实验设置；
- 肯定、否定和不确定程度；
- 因果关系与相关关系；
- 数据、模型、语言和任务范围；
- 论文标题、模型名、数据集、benchmark、公式和代码标识。

中文内容中的阿拉伯数字必须能在绑定的 abstract 或 PDF 中找到。原文只说“improves”时，不能补写具体提升幅度；原文只报告相关性时，不能改写成因果作用。

## 三、语言要求

- 默认使用直接、具体的中文。
- 模型名、数据集名、benchmark 和指标保留英文，例如 `Llama`、`MMLU`、`Pass@k`。
- 通用概念第一次出现可写成“中文（English）”，后文使用中文简称。
- 避免内部工程表达，例如“门禁、契约、赋值、核验、工件”。
- 避免“本文基于……进行……从而实现……”一类连续套话。
- 一句话只承担一层主要意思，长定语拆成两句。

## 四、普通摘要示例

### 合格

> 论文研究多轮工具调用中计划与执行状态容易脱节的问题。作者把高层任务规划和具体工具操作拆成两个模块，并用执行结果持续更新下一步计划。在论文报告的任务上，该方法提高了完整任务成功率，也减少了无效调用。实验集中在给定工具集合和模拟环境中，尚不能说明它在开放环境中同样稳定。

这段话说明了问题、方法、结果和范围，没有添加原文之外的数字。

### 不合格

> 本文提出了一个非常先进的 Agent 框架，显著解决了所有工具调用问题，具有广泛的落地价值。

问题包括：使用空泛评价；把有限实验扩大到“所有问题”；没有说明方法；“广泛落地价值”没有来源。

## 五、获奖解读示例

### 研究问题

> 现有评测通常只看模型能否偶尔完成任务，却没有区分一次成功和多次稳定成功。

### 核心方法

> 论文同时报告 Pass@k 与 Pass^k：前者观察多次尝试中是否至少成功一次，后者观察模型能否连续稳定完成任务。

### 主要发现

> 两项指标呈现出不同的模型排序，说明“有机会成功”不能直接代表“适合稳定运行”。具体数值和实验设置见页面下方的论文原文结果。

这里保留了指标名和判断边界，没有把网站解读写成作者或会议的官方评价。

## 六、提交前检查

- `summary_zh` 是否为 150–250 个中文字符？
- 是否覆盖研究问题、核心方法和主要发现？
- 每个数字是否存在于绑定来源？
- 模型、数据集、benchmark 和指标名称是否准确？
- 是否把相关性误写成因果关系？
- 是否扩大了论文的肯定、否定或适用范围？
- “局限”是否来自论文或清楚可见的实验范围？
- 中文读出声是否自然？
- 信息不足时是否直接说明，而不是补写套话？
